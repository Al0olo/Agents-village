# Writing rules

- Plain, specific, short. Lead with the point. No padding, no filler adjectives, no
  restating the question.
- Documents for readers contain no process narration ("the review found", "after the
  red-team", "I verified"). State the result. Dates belong in the byline or the log, not
  scattered through the text.
- Prefer prose; use a list or table only when the reader will scan or compare.
- One term per concept. Use the project's words: citizen, village, ledger, admission,
  hearsay, fact, block, arm, fork.
- Link, do not paste. Keep READMEs short and AGENTS.md files to rules an agent can act on.
- `docs/HANDOFF.md` is the exception: it is working state for the next agent and may be
  terse and operational, but it must still be unambiguous.
